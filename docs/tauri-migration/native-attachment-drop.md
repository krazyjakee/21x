# Native attachment drop ownership

The native-only drop protocol uses the existing held-file selection/import
owners. It grants no arbitrary pathname read, Source operation, Source event,
mobile event or new task/project permission. Production raw attachment schemes,
DOM file paths and `webUtils.getPathForFile` remain unavailable.

## Public facade and private receipts

The generated optional desktop surface is:

```ts
attachments.setNativeDropContext?(contextId: string | null): Promise<void>
attachments.onNativeDrop?(listener: (receipt: {
  dropId: string
  contextId: string
  paths: string[]
  accept(): Promise<void>
  close(): Promise<void>
}) => void): () => void
```

The renderer owner supplies a fresh lowercase UUIDv4 for one eligible ordinary
task or new-task draft view. The nonce carries no task/provider/grant authority;
reopening the same task needs a new nonce. Group/Captain attachment mutation has
no domain contract and remains unavailable. Engineer A owns these UI lifetimes
and the sequential save/explicit metadata update integration.

Explicit native bootstrap availability and a current physical-document receipt
are required. Registration also carries a private, monotonic document-bound
`contextRevision`, generated by the facade. Native rejects a delayed older
request *arrival*, as well as a late response. Replacement/null intent fences
old admission synchronously and acknowledges the new context only after joined
old-group cleanup. A failure retains cancelled ownership for retry. Retired
nonces cannot be revived; context/drop tombstones are bounded to 4096 each.

An actual Tauri OS `Drop` captures the original physical document and already
acknowledged context before any await. It never activates a document or finds a
replacement context at delivery time. A native drop identifies its physical
target even while keyboard focus stays with the file manager. Native rechecks
the original completed, trusted, visible document/context through descriptor
acquisition, Source offer and delivery. Wrong tickets, retired documents,
foreign epochs and missing contexts refuse before import.

The separate `desktop:attachment-drop` event contains exactly
`{engineEpoch,leaseId,drop:{dropId,contextId,paths}}`. It is targeted to the captured
main WebView, not the general `desktop:event` stream. Paths are display strings
for private selection IDs; at most 16 unique paths and 16 active groups are
allowed. FD acquisition retains existing no-follow ancestors, regular-file,
protected-profile, version/digest, 64 MiB/file and bounded read rules.

## Two-phase delivery and cleanup

`accept()` records local ownership synchronously before returning its promise.
Native acknowledges only the exact current group/context/document. File reads
are denied until that acceptance. The consumer must await the receipt before
calling existing `attachments.save`, which still returns metadata without
implicitly appending it. Functions never cross a native/Source DTO boundary.
For a draft, the view retains the accepted receipt until its pending files are
imported into the accepted task or the draft is retired; closing immediately
after displaying pending paths would revoke those future imports.

Absent, ambiguous, ignored, throwing or rejected consumers are closed by the
facade. Unaccepted native groups stop admission after 15 seconds and join their
actual cleanup; the TTL never manufactures an early drain acknowledgement.
Replay cannot redeliver or close an already accepted receipt. Unsubscription,
reconnect, navigation, destruction and shutdown retire the original intent.
Old listener callbacks cannot target a new connection even in the same epoch.

`close()` first fences new work, joins its raw accept, then uses the exact native
receipt-only cleanup route. Native joins raw capture/offer, invokes private
`engine.attachment.selection.revoke` for its IDs, joins Source's admitted raw
read/import/native-retire receipts, and closes held descriptors. Cleanup remains
usable for the captured old document and during stopping. It neither acquires a
new selection nor closes the parent SDK or unrelated flows. Failure retains
cancelled ownership for an explicit retry; success is idempotent and never
repeats acceptance/import. Already accepted destination copies survive close.

Tauri's built-in drag notifications can expose display paths and update its
internal file scope. This production configuration provides no filesystem
plugin or raw asset protocol grant. The real Wry control separately rejects a
raw dropped-file asset fetch under the production CSP; import still uses the
private descriptor route.
