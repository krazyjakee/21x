# Task group request authority

The production task-group service enters the actual AgentManager through `withTaskGroupRequestGuard(effect, beforeEffect, signal)`. Its AsyncLocalStorage scope follows nested `startTask`, admission, resume, durable sends, MCP configuration, and workspace preparation. The guard calls current owner/caller authorization at real effect boundaries and after external waits; cancellation also fences those boundaries. Calls with no request scope retain the existing manager behavior. Scopes are limited to 64 concurrent requests and eight nested levels.

A request promise does not stand in for raw completion. The manager retains actual startup, prompt, configuration, and cleanup children in its shutdown work; the scope also joins registered children before returning. Deadlines and authority withdrawal can reject the public request while an ignored-cancellation SDK operation is still owned. Shutdown drains that raw work before profile/database release. Task-addressable startup receipts survive public deadlines: group definition checks still see ownership, new starts/messages cannot duplicate an uncertain startup, and Stop joins the raw create/resume and late cleanup acknowledgements. A child registered late remains drainable but inherits a closed scope that cannot authorize a new effect.

Worktree metadata fallbacks and clone/fetch/worktree sequences check the optional guard before subsequent commands, directory mutations, and publication. Accepted commands still run to actual acknowledgement. Workspace SKILL.md, AGENTS.md, and CLAUDE.md writes check before each next write. MCP token refresh carries the request guard through the actual OAuth owner to its token commit and failure handling; revoked callers cannot trigger a subsequent token write, deletion, notification, provider fallback, or prompt. Ordinary unscoped OAuth refresh still persists an accepted rotated credential during orderly shutdown.

If native creation or resume acknowledges after withdrawal, the manager retains its exact native identity and joins acknowledged teardown. A refused cleanup retains runtime ownership, blocks another start/send, and prevents a successful shutdown release. An ambiguous foreign native identity is retained as a cleanup conflict rather than destroying another task's session. Durable messages that lose authority before dispatch become cancelled, and cancelled starts are not automatically retried. Real backend acceptance and continuity acknowledgements remain truthful receipt bookkeeping; an already accepted provider prompt cannot be retracted or blindly replayed.

Accepted polling, transcript invalidation, admission queue processing, and recovery timers explicitly detach into manager ownership. They do not inherit a completed caller's guard. Accepted stop/destroy cleanup also detaches after admission and uses captured native config instead of starting a new OAuth refresh. This does not detach a new caller-requested admission or prompt. Background sessions still follow admission, manual stop, approval, provider-recovery, and generation checks.

Authored tests cover ignored cancellation, nested and independent scopes, raw cleanup joins, closed inherited callbacks, real SQLite/group anchors with controlled adapters, initialization/create/resume/config barriers, failed native cleanup, accepted polling, guarded OAuth rotation, and real workspace file writes. Controlled adapters are process-boundary fixtures; they do not establish live SDK, CLI, credential, or installed-platform acceptance.
