# Local recognition owner

`VoiceSessionManagerCore` owns the existing recognition state machine without importing Electron. Its host must supply the actual database, AgentManager, recognition worker, model manager, runtime owner and speech owner, absolute model/runtime roots, desktop event sink, and explicit microphone, shortcut and action capabilities. `assertOwners` verifies those exact borrowed identities. The Electron `VoiceSessionManager` wrapper keeps the original imports, constructors, system permission and global shortcut behavior.

The production portable host currently declares microphone capture, shortcuts and command actions unavailable. A saved enabled preference does not grant those capabilities or start a worker. Management can read real runtime/model metadata and change admitted preferences; requesting a native microphone turn or unavailable shortcut/custom-directory effect refuses before its setting write. Command actions remain disabled until the existing VoiceActionService has exact task lifecycle, group/reference and current HITL request ownership. There is no alternate voice task writer.

`runManagementMutation(effect, beforeWrite)` serializes management across recognition and speech, invoking the current grant before admission and after asynchronous work before settings/filesystem writes. The nested model/runtime/speech guards preserve that same lease. Competing unleased writes refuse. Accepted work is never automatically replayed after a caller disconnects.

`shutdown()` fences new work and late worker events/settings writes, cancels turns and downloads, and signals the owned children. `close(timeoutMs)` joins actual initialization, model downloads, recognition/action completions, response-body cleanup, child pipe/process close and the speech owner. A deadline reports incomplete draining while the receipts remain owned; kill requests and process errors alone do not release them. The host keeps the database/resources open until these drains finish. Worker replacement waits for the previous child; only registered ChildProcess objects are signalled. Public worker errors are fixed messages and raw native diagnostics are drained without publication.

Portable models use the constructor-frozen verified catalogue, safe model IDs, bounded directories/files, no linked paths, exact size/checksum validation and exclusive temporary files. Publication cannot replace a preexisting destination. Removal waits for downloads and refuses mismatched bytes, symlinks, unknown contents or changed identities; unknown legacy trees and user files remain untouched. Owned temporary cleanup checks parent/file identities. Portable reads omit unknown legacy directories rather than inventing supported model IDs. These checks reduce filesystem races; they do not claim atomic kernel containment against every same-user concurrent path change on every OS.

The existing Electron model download path retains its range/resume behavior. Portable downloads now use `VoiceModelDownloadPolicy` with manual redirects and omitted credentials. Only exact verified URLs from the manager's constructor-frozen catalogue may start a download. The four existing publisher/repository/revision tuples are separately fixed in the policy; moving branches, mirrors, other repositories and user URLs cannot create a grant. Relative cache redirects must retain the same repository, revision and source filename. The cache's encoded empty query reference is admitted only when it equals that exact original pinned resolve path; foreign references or nonempty values refuse.

The reviewed CDN subset is exactly `cas-bridge.xethub.hf.co`, `us.aws.cdn.hf.co` and `us.gcp.cdn.hf.co`, over HTTPS with no explicit port or userinfo. Its resource path is `/xet-bridge-us/<24 lowercase hex>/<64 lowercase hex>`. The first approved Hugging Face response must bind the pinned commit, linked file SHA256, linked exact byte size and the separate Xet CAS hash. A later CDN redirect may change reviewed host or signed URL parameters, while retaining the exact bound object path. The Xet CAS hash is never substituted for the manifest file SHA256. Signed publisher capabilities remain private to the raw request and are never included in public errors, progress or logs. No Authorization/Cookie header is forwarded. The manager still verifies exact final received size and SHA256 before exclusive publication.

Every response has bounded headers (64 names and 16 KiB aggregate UTF8 metadata), and only finite public signed-URL parameter names are admitted. Unknown parameters, private Xet identities, changed resources, ambiguous metadata, encoded/dot-segment paths, host suffix lookalikes, HTTP, local/private host spellings, credentials, fragments, cycles and a fifth redirect refuse before another request. Intermediate response reader cancellation/release completes before the next request. A 20-minute aggregate portable-install deadline signals cancellation; ignored fetch, reader cleanup and filesystem work remain owned until they actually settle. Current caller/owner grants and cancellation are checked before each request, file write, sync and publication.

Primary-source review on **2026-10-14**:

- [Hugging Face model download documentation](https://huggingface.co/docs/hub/models-downloading) describes HTTPS CDN redirects and names the US AWS/GCP endpoints. [Official endpoint metadata](https://huggingface.co/.well-known/meta.json) additionally lists regional hosts. This policy deliberately does not admit every published endpoint or any wildcard; future infrastructure changes require another source review.
- [Hugging Face's migration-to-Xet article](https://huggingface.co/blog/migrating-the-hub-to-xet) describes the non-Xet client's bridge redirect and the `cas-bridge.xethub.hf.co/xet-bridge-us/` namespace. [The backward-compatibility documentation](https://huggingface.co/docs/hub/xet/legacy-git-lfs) explains that the bridge reconstructs one file for legacy HTTP clients.
- [Official `huggingface_hub` file download source](https://raw.githubusercontent.com/huggingface/huggingface_hub/main/src/huggingface_hub/file_download.py) uses linked ETag/size/commit metadata and removes HTTP authorization for separate CDN requests. [Its Xet metadata parser](https://raw.githubusercontent.com/huggingface/huggingface_hub/main/src/huggingface_hub/utils/_xet.py) reads `X-Xet-Hash` separately from the linked file digest.
- [Sherpa's own model documentation](https://github.com/k2-fsa/sherpa-onnx/blob/master/sherpa-onnx/c-api/docs/offline-asr.dox) names the Parakeet v3 int8 package/files. The application manifest supplies the existing fixed publisher tuples, revisions, hashes and byte sizes. Direct catalogue blob/API pages were unavailable through the browsing tool. A subsequent coordinator probe using the actual policy and pinned standalone Node followed the exact Parakeet `tokens.txt` publisher/cache chain and verified all 93,939 bytes against catalogue SHA256 `d58544679ea4bc6ac563d1f545eb7d474bd6cfa467f0a6e2c1dc1c7d37e3c35d`. This proves one small token-file transfer; it does not prove a live CDN/binary transfer, a complete model install or inference. [Batch evidence](evidence/issue-closing-20261014-local-model-receipts.json) retains the initial refusal, sanitized publisher metadata and final result.

The policy implements the reviewed public bridge/CDN subset, rather than native Xet protocol, LFS resource layouts, alternate regions or hosted inference. Mocked public publisher redirects drive real temporary file/hash/stream tests for publication, resource rejection, ignored aborts, deadline expiry, stale grants and cleanup retention. Live model download usability and installed inference remain release-proof gates.

`VoiceRuntimeOwner` bounds installed package manifest reads and checks physical directory/file identities. Portable installation refuses before npm or filesystem effects because the legacy `sherpa-onnx-node` installer is unpinned. Removal of an installed runtime refuses without a trusted inventory of its shared dependency bytes. The Electron compatibility host retains that existing installer/removal path, now with process-close receipts and cancellation. No portable runtime version or installed-platform success is inferred from reading a manifest.

Authored regressions cover actual portable SQLite settings/owners, unavailable native effects, grant replacement, late initialization/download shutdown, shared management serialization, complete status payloads, ignored fetch/body cancellation, swapped model parents and user-file preservation. POSIX child fixtures use explicit standalone Node, real IPC/pipes and an ignored SIGTERM to verify close ownership, replacement isolation and preservation of an unrelated child. Windows ignored-signal behavior is outside those fixture assertions. No validation result is claimed by this document; the coordinator runs the integrated suites after owner freeze. Native microphone capture, installed models/runtime, all-platform packaging and historical voice cutover remain open #218 gates.
