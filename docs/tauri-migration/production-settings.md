# Production settings and secret boundary

`ProductionSettingsBackend` replaces the production profile's synthetic-only settings binding with eight reviewed commands. It borrows actual DatabaseManager, AgentManager, recurrence, heartbeat, automation, scheduled coordination, workspace cleanup and authenticated secret storage identities. Root binding asserts those objects belong to its singleton. Codec availability and finite operation names do not supply mutation authority or prove installed application parity.

| Command | Contract and actual owner |
| --- | --- |
| `settings:get` | Finite key name, separate setting/project/global read grant; missing returns `null`, saved empty remains `''`, nonempty credential returns the existing saved-key marker |
| `settings:getAll` | Authorized declared keys only; reads key names first, never decrypts unrelated internal rows; credentials are markers |
| `settings:set` | Separate write grant, bounded per-key format and reference validation; actual database serializer; global cap drains real admission, global pause uses the actual manager |
| `secrets:getAll` | Global/secret read scope; exact metadata columns only, never plaintext values or encrypted BLOBs |
| `secrets:create` | Explicit create/environment-name grant; actual authenticated encrypted BLOB write; result contains metadata only |
| `secrets:update` | Secret, referring-agent and affected-project write grants before actual credential owner teardown; omitted value preserves saved ciphertext, empty value is an encrypted empty secret |
| `secrets:delete` | Same scope/preflight and real owned teardown; removes authorized `secret_ids` references while preserving unrelated agent configuration/history |
| `env:get` | Only `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `CURSOR_API_KEY` presence; separate host grant; marker/empty/null, no environment plaintext |

The finite settings inventory is `PRODUCTION_SETTINGS_KEYS`. It includes provider keys, public chat configuration, global admission/pause, current project/default agent, heartbeat/cleanup preferences, briefing/managed-session policy, bounded legacy canvas/drawing persistence, setup and UI preferences. Only the declared canvas/drawing bases may have a validated `:<projectId>` suffix, and that project must exist and be authorized. Neither a prefix wildcard nor a key ending in `_api_key` grants access. Live mobile auth/pairing codes, OAuth tokens, internal Commander memory/generation pointers, session completion markers, schema versions and other bookkeeping are excluded from both individual reads and enumeration.

Default-agent and chat-agent references must name existing authorized agents; current-project references must name an existing authorized project. Reads also respect reference visibility. Global admission/default mutations check future-dispatch project scope; chat provider-key writes check the selected chat agent's read scope. Secret edits check every referring agent and its task/default/Captain project references, plus the actual manager's shared-adapter expansion. The referring set is frozen and rechecked after Stop; a new unfenced reference rejects the write. Source-linked internal settings have no generic grant. Source/OAuth/connector operations remain with their own scoped owners.

Consumed OpenAI/Anthropic provider-key and secret mutations use `runCredentialMutation`, supplied by the actual production owner; input cannot provide an affected-agent array. Those global provider setting keys feed Chat/Commander, while coding SessionConfig uses the separate agent configuration keys. Root synchronously fences/cancels/joins accepted Chat/Commander work and scheduled coordination for their provider-key changes. Its actual provider-stream owner also joins briefing and Captain recap streams and rejects retained obsolete provider references and serializes the write; unrelated coding sessions remain intact. Google/Cursor global keys use the same authenticated database serializer as stored credentials, without claiming an active provider consumer or running an unrelated lifecycle fence. Default-agent selection fences admission around a future-dispatch preference write and drains the queue while preserving accepted live work. Secret edits derive referencing coding agents; a cached shared adapter with configuration notification also fences and acknowledges its actual shared owners before refresh. Stops, pending creations, queued references and backend notifications remain actual lifecycle work. An accepted write is neither undone nor automatically repeated because notification or transport delivery later fails. Secret create has no previously bound agent to retire; database uniqueness remains authoritative.

Credential writes require the exact registered provider and `21x.aes256gcm.v1` format with encryption available. Provider strings preserve whitespace, multiline Unicode and leading BOM; reads use DatabaseManager's versioned credential-setting codec and return only `__21x_api_key_set__` when nonempty. Echoing that marker does not replace the saved key or re-run mutation effects. Clearing a provider key preserves `''`; omitted secret update values preserve the existing BLOB. Incompatible/unknown stored credential envelopes fail visibly without conversion or guessed decryption. The boundary does not export ciphertext, auth tokens or values in errors/events. Agent `config.api_keys` uses the separate production AgentConfigurationBackend and versioned record-credential serializer; authenticated profiles encrypt it and return vendor markers. It is not edited by the generic settings route. See [agent configuration](agent-configuration.md).

Environment reads expose presence only because the actual AgentForm uses their truthiness. Secret library environment names use bounded shell-identifier syntax and an explicit host grant. Process-control names such as PATH, NODE_OPTIONS, preload variables and task API/MCP credential namespaces are refused before encryption or owner effects. This is distinct from a grant to read process environment or a renderer-provided environment map.

Runtime voice/model/shortcut/TTS/ElevenLabs and minimize-to-tray settings are bounded readable names, but writes are refused before persistence because their actual native owners are absent in this production slice. UI-only advanced voice display preferences may be stored. User identity, Forgejo auth selection, recorded repository-provider mapping and executable-path settings are read-only here; their proper owners must implement edits. No successful native no-op hook is supplied. This preserves explicit failures rather than reporting a native effect that never happened.

Registered schedulers consume their preferences on their existing cadence. Merely saving a cleanup preference does not trigger filesystem/process cleanup, and saving a briefing preference does not launch a paid model turn. Global admission/pause changes use the immediate real manager effects. Changing stored Captain prewarm/UI configuration preserves its existing future-consumer behavior; background prewarming parity is separate #212 work.

Cancellation before a database effect prevents it. Accepted external Stop/config work and accepted writes remain retained through late cancellation; their replies may be suppressed, their raw promises are still drained, and accepted invalidation is still delivered once. `close()` rejects new admission and joins retained work; a timeout retains the profile/database/storage/owner lifetime. Fatal invalidation is latched and surfaces a fixed redacted error. Credentials/metadata use exact legacy API result types, including void/undefined/null/empty/false. Requests/results cap at 900,000 UTF-8 JSON bytes; secret lists cap at 128 metadata records and setting enumeration at 512 keys. Oversized data fails visibly without truncating storage.
