# Secret broker and shell ownership

`SecretBroker` is a portable loopback HTTP owner with an explicit credential source. Concurrent starts share one bind. Each listener generation owns its token scopes, port and source; an old listener cannot consult a replacement generation's database. Scope registration copies the secret IDs, revocation takes effect immediately, invalid environment names are filtered, and exports retain the existing Bash quoting and PowerShell base64 representation. Responses disable caching; failures disclose neither credentials nor token fragments.

Shutdown closes admission, revokes tokens and waits for an outstanding bind before closing the listener. Successful close requires the native close acknowledgement and releases the source. Partial HTTP connections are destroyed. A bounded deadline fails with `SECRET_BROKER_SHUTDOWN_INCOMPLETE`; the actual close remains owned and a later close can join it. Native close errors retain the same listener for retry.

The Electron adapter supplies the application profile path and owns active and retired broker generations. Final application shutdown refuses restart and wrapper creation before accessing the profile, joins all retired listeners before SQLite close, and stops exposing a broker port immediately. Startup now binds the broker and writes the wrapper before agent reconciliation and scheduler startup.

Shell generation takes an explicit profile directory. Bash and PowerShell log paths are quoted literally, including apostrophes and shell metacharacters. PowerShell request errors use a fixed message because exception text can contain the credential-bearing URL. Both wrappers remove broker variables even when credentials were incomplete. Commands and exported values stay out of logs, and exports remain in memory.

Nine portable core cases exercise actual loopback requests, generation isolation, copied scopes/revocation, quoting/base64, rejected requests, in-flight startup, partial connections, held native close, timeout/retry and native errors. Two platform wrapper cases use an owned temporary profile, synthetic values and the owning Node executable. The Windows case uses system PowerShell; its [hosted run at `e247073`](evidence/secret-broker-windows-scenarios.json) passed both actual wrapper cases and the native terminal fixture, with 1,530 default portable tests / zero skips in 102 files overall. One application owner case joins replaced generations and rejects source revival. Existing broker tests remain in the application suite, including the optional PowerShell Core test.

See [local evidence](evidence/secret-broker-owner-local.json).
