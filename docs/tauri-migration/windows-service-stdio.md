# Windows service stdio continuation

Scoped work for [#204](https://github.com/krazyjakee/21x/issues/204), [#208](https://github.com/krazyjakee/21x/issues/208) and [#222](https://github.com/krazyjakee/21x/issues/222). The original three Unix agent targets passed, while Windows stopped before packaging. After the CRLF/reporter corrections, its service disconnected during initialize. The [service-only diagnosis at `3d3ff98`](https://github.com/krazyjakee/21x/actions/runs/38327288299) identified `startup-stdio`, exit code 1, with no GUI/native compilation requested.

The old check required `fstat` to classify both descriptors as FIFO/socket. The pinned Node implementation wraps inherited PIPE/TCP streams in `net.Socket`, wraps files in filesystem streams, and wraps terminals in TTY stream subclasses. Its Windows libuv `fstat` handles file, TTY and named-pipe types; it does not establish that every child-launcher socket is a filesystem-stat socket. [Node 22.23.2 stdio implementation](https://github.com/nodejs/node/blob/v22.23.2/lib/internal/bootstrap/switches/is_main_thread.js), [libuv Windows fstat implementation](https://github.com/libuv/libuv/blob/v1.51.0/src/win/fs.c).

The Windows bootstrap now checks the actual process stdin/stdout socket classes, descriptors 0/1, readable input, writable output, open streams and non-TTY handles. A filesystem stream or terminal fails before protocol startup. POSIX retains its existing descriptor-stat check. This identifies usable inherited stdio; the native supervisor still owns the child and its private handles, and native WebView authority remains the caller boundary. It does not introduce a network listener, a caller-provided stream or a production bootstrap.

Actual bundled negative controls cover both file-directed input and output, unsupported runtime and invalid profile/resource roots. They require unsuccessful exit, the expected fixed classification and no sensitive-path echo or protocol output. Positive private-pipe initialization, durable pages/configuration and agent approval remain required on the actual Windows runtime. Local Unix controls do not establish Windows acceptance; the platform retry records its own source and result.

Synthetic platform steps run these five controls and the actual transcript proof under staged Node before proceeding. They retain JSON and require exactly six passing cases with zero skips. This prevents a missing service bundle or unselected test graph from silently counting as a platform startup proof.

The same continuation owns Interrupt calls and inactivity-reaper sweeps through shutdown. Interrupt verifies the exact session generation after configuration/provider awaits, so a late result cannot publish idle status for a stopped/replaced session. Reaper sweeps coalesce while a tool probe is pending, recheck generation/activity/subtask work after the await, and stop before database access during shutdown. Eight regressions cover held interrupt configuration/success/error, a held shutdown reaper probe, newly working/recently active/replaced sessions and newly running child work. The existing normal interrupt/reaper cases remain part of the manager regression suite.
