# Production agent CLI detection

`AgentInstallerBackend` binds the existing `agent-installer:detect` command to the production owner's actual `PortableAgentDetectionOwner`. The payload remains empty. It requires current trusted desktop identity, exact borrowed-owner availability and a separate configuration **read** grant. Neither request arguments nor a transport manifest can choose an executable, environment, home, directory or setup command. A revoked grant suppresses a late result without replaying probes.

Detection retains the thirteen shipping keys: Node, npm, pnpm, Git, GitHub CLI, GitLab CLI, Tea, RTK, Claude Code, OpenCode, Codex, Cursor and Pi. Each result keeps its actual installed/version state. Pi retains the minimum `0.80.5` support check and corresponding reason; RTK retains genuine integration booleans and requires integrations for all installed supported backends before showing configured. Unknown version output remains `null` on the portable path. Bounded version syntax and fixed failure text prevent raw command stdout/stderr, paths or credentials from becoming public diagnostics. A successful version probe is not backend health or permission to start an agent.

The host captures approved absolute home and working directory, plus a finite immutable environment snapshot. Allowed names are `PATH`, `HOME`, `USER`, `LOGNAME`, `TMPDIR`, `TEMP`, `TMP`, `SystemRoot`, `WINDIR`, `COMSPEC`, `PATHEXT`, `USERPROFILE`, `APPDATA` and `LOCALAPPDATA`. The owner forces HOME to the approved home, rejects other keys such as NODE_OPTIONS/provider tokens, removes relative/empty PATH entries and adds the same user OpenCode/local install directories in its private copy. It never changes process-global PATH or HOME. Absolute Pi fallbacks must remain within the approved home or captured PATH directories; an unapproved npm-prefix location cannot broaden execution authority.

All probes use the fixed existing version arguments, plus npm's fixed `prefix -g` query. No install, download, shell evaluation, package setup, model request or RTK initialization occurs. POSIX probes use direct spawn with a private environment. Windows resolution is limited to known executable/wrapper extensions; `.cmd`/`.bat` probes use the captured system command interpreter with AutoRun disabled, fixed arguments and constrained quoting. This source implementation is not installed Windows execution evidence.

The real owner admits at most two snapshots, four concurrent child/read jobs and 32 queued jobs. Each child captures at most 65,536 combined stdout/stderr bytes. Probes have a maximum ten-second deadline and snapshots a thirty-second deadline. Timeout, cancellation, stream failure and overflow request termination of the exact registered child; a bounded escalation follows. Ownership remains until the actual child close receipt, including delayed pipes. It does not kill process groups, descendants or unrelated PIDs. If acknowledgement is incomplete, `close()` fails visibly and retains raw work; the host cannot treat a kill request as proof that resources drained. Both raw snapshot promises and individual process/filesystem jobs remain tracked.

RTK integration checks use the five existing known files beneath the approved home. Async reads cap each regular file at 262,144 bytes. They reject file/directory symlinks, special files and oversized data, compare the final lstat identity with the opened descriptor, and recheck home/parent/file identities before exporting the marker boolean. Changed size/timestamps also refuse the result. The descriptor is closed even after refusal. Linux uses O_NOFOLLOW where available; lstat/identity checks provide additional refusal paths where that flag is unavailable. These checks establish their stated read/race detection scope, not an atomic kernel containment guarantee on every OS or filesystem. Missing, unsafe or unrecognized integration files report false; configuration files are never modified.

The boundary cancels its own accepted requests on shutdown and drains them. The production owner also stops/drains its borrowed detector before releasing lifetime resources. Failed callbacks and late replies use fixed public protocol messages; no probe is automatically retried beyond the existing finite Pi location fallback list. The existing Electron detection path keeps its compatibility behavior and install-directory refresh semantics; portable detection is explicitly selected by the new owner.

Authored tests exercise real local Node child programs with fixed synthetic version output, real process exit, output limits, per-probe timeout, ignored cancellation and shutdown escalation. They check finite environments/concurrency, fresh missing/Pi snapshots, real RTK files, file/parent replacement refusal, actual stream fault ownership, unrelated-child preservation, grant/epoch/input rejection and bounded admission. Codec and legacy detector regressions cover exact status fields, minimum Pi semantics, nulls, fixed errors, RTK readiness and portable PATH isolation. POSIX fixture execution is scoped to the host platform; it proves local process ownership, not installed real CLI/backend parity. No worker tests or checks were executed.

`agent-installer:install` remains unbound and unavailable before effects. Full #213 remains open for installer execution/native ownership, packaged backend/platform evidence and the remaining authenticated API/MCP/plugin/secret-broker integration gates. This implementation authorizes no release, hosted #92 work or live-profile cutover.
