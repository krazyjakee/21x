# Owning Node runtime for workers

Scoped preparation for [#211](https://github.com/krazyjakee/21x/issues/211), [#214](https://github.com/krazyjakee/21x/issues/214), [#218](https://github.com/krazyjakee/21x/issues/218) and [#222](https://github.com/krazyjakee/21x/issues/222). The shared worker selector previously applied Electron rules in every process: macOS selected bare `node` from PATH, while other systems added `ELECTRON_RUN_AS_NODE`. A future packaged standalone service would therefore lose its bundled runtime on macOS.

The selector now distinguishes an Electron owner from a standalone owner using the actual process runtime, with an explicit kind available for host tests. Standalone workers reuse the exact absolute owning executable on every platform and remove the Electron mode flag from a copied environment. Relative/PATH executable names reject. Legacy Electron behavior remains characterized by its existing tests. Voice recognition/TTS fork clients and Pi's non-Windows invocation use this selector; Windows Pi's installed CLI launcher remains a separate provider-parity requirement.

Ten standalone cases cover the three legacy platform selections, three bundled executable selections, three relative-name rejections and a real-file IPC child. The actual child runs with PATH empty, reports the same Node/executable, confirms no Electron runtime/mode and completes a ping before disconnect/close. The parent joins normal exit and bounds cleanup on failure. This tests worker runtime selection and actual Node IPC, not speech model loading or a real provider session.

The standalone suite includes these tests. The existing Pi/voice caller suites also run under the legacy launcher with their original mocks and environmental skips. Worker entry/resource staging, complete production transport/ownership, audio/PTY throughput, voice permissions/models and real provider parity remain tracked by their owning issues. No production worker or optional speech runtime is installed or activated by this change.

The connector continuation fixes a separate late-start race: `PieceHostClient` could await credentials past cancellation, timeout or disposal and then create a new worker. It now checks disposal, abort and the exact active call before host creation. Four regressions hold the credential read across those exits and across a subsequent call. All fourteen piece-host/client cases pass under both staged standalone SQLite/Node and the legacy launcher. The portable suite includes this graph; production connector worker transport, raw credential/KV drain ownership and Node-host entry staging remain open #208/#216 work.
