# Production task source boundary

`TaskSourceBackend` binds eight retained commands to the actual DatabaseManager, SyncManager, PluginRegistry, OAuthManager, AgentManager and registered task schedulers. The production owner supplies exact borrowed-owner/storage assertions, trusted desktop identity and separate project/task/source/MCP/connector grants. A source configuration, URL or transport manifest never grants a plugin, browser, CLI or connector worker capability.

| Command | Actual behavior |
| --- | --- |
| `taskSource:getAll` | Project filter or all authorized projects; omitted/empty filter retains legacy behavior; finite public metadata and credential presence markers |
| `taskSource:create` | Existing authorized project and referenced MCP/connector identities; finite plugin/config; real encrypted database writer; defined source result |
| `taskSource:update` | Rechecks source/project/affected task references after accepted sync drains; public config merge preserves stored credentials; missing source returns `undefined` |
| `taskSource:delete` | Waits for accepted source jobs, preflights cascade scope/group protections, fences actual task owners, acknowledges Stop and performs per-task cleanup; missing source returns `false` |
| `taskSource:sync` | Actual plugin import and durable task/source checkpoint writes; no automatic effect replay |
| `taskSource:exportUpdate` | Actual task lease and source job ownership; finite export fields; existing `complete_at_source: false` policy removes status from the source update |
| `taskSource:getUsers` | Separate source/project read grants and an actually available plugin user capability; bounded exact `{id,email,name}` records |
| `taskSource:reassign` | Actual task/source leases through the remote result and local assignee write; a foreign replacement binding cannot receive the accepted result |

Source DTOs retain the existing fourteen fields. Config keys are declared per shipping plugin: Linear, HubSpot, GitHub issues, Forgejo issues, Notion, YouTrack and connector bridge. Unknown config and legacy tool arguments remain stored and are excluded from the public DTO; newly submitted nonempty legacy tool/argument execution is refused. Saved inactive or unknown plugin metadata remains readable and supports name/enabled edits. Unknown plugins expose empty config and cannot run effects or receive new config. This is metadata retention, not an arbitrary plugin execution grant.

The finite credential fields are `linear.client_secret`, `hubspot.client_secret/access_token`, and `notion/youtrack.api_token`. Raw write-only values permit at most 16,384 UTF-8 bytes, preserve Unicode/BOM/multiline data and reject NUL. The actual authenticated-profile database serializer protects these fields; the registered storage identity and encryption availability are checked before work. Public nonempty values become `__21x_api_key_set__`; an explicitly cleared secret remains `''` in storage and its presence marker disappears from the public config. A marker requires an existing nonempty string. Marker-only updates omit config mutation entirely, retaining ciphertext and `last_synced_at`; unrelated config merges reuse unchanged ciphertext exactly. OAuth tokens and connector session/persistent credentials retain their separate existing owners and encrypted formats. Unsupported/malformed envelopes are not guessed or converted. Production startup rejects protected plaintext profile rows before migration; this boundary authorizes no live-profile conversion.

SyncManager reserves per-source FIFO jobs and immediately fences new jobs when mutation is pending. It drains previously accepted manual import/export/action/user/reassign work before mutation. The actual connector bridge scheduler is bound to the same owner before polling starts; scheduled sync keeps `manual: false`, its existing timer/retry rules and durable connector cursor. A failed/partial import does not advance `last_synced_at`, which is an incremental cursor for built-in sources; accepted task writes and bridge retry/cursor state remain stored. Polling admission may resume after mutation without a renderer. Source configuration edits preserve connector instance/cursor identity and refuse silently sharing an instance with a second source. Task lifecycle reservations prevent ordinary delete/move/group edits from racing export/reassignment. Deletion also scopes descendants and surviving parent/sibling updates; grouped/coordinator cascades and cross-source descendants are refused before Stop. These guards do not replace the existing task-group review or source-completion policy.

Before materializing stored JSON, the boundary checks source/task row byte lengths. A single row or aggregate affected records may occupy at most 512,000 stored bytes; list reads scan at most 4,096 identifiers, return at most 256 sources and materialize at most 512,000 aggregate source bytes. Source mutation/effects cap affected task references at 128. Public request/reply frames cap at 512,000 UTF-8 JSON bytes; users cap at 512 records. Oversized legacy rows fail visibly with stored bytes unchanged. New mutations validate persisted size and public projection within their database transaction.

Cancellation before an effect prevents it. An accepted provider/Stop operation remains retained through ignored cancellation and shutdown, and accepted task/checkpoint/assignee writes reconcile under their original owners. A suppressed reply does not undo or repeat the remote operation. `close()` fences new boundary admission and joins raw work; a timeout retains ownership. The production host must also join SyncManager, connector bridge/runtime and agent owners before releasing SQLite/profile resources. Accepted invalidation failure is fatal and latched without retrying the mutation. Source import diagnostics contain fixed failure messages/counts, never raw provider error/config/token text; public sync/reassignment errors preserve failure visibility without exporting provider messages.

Authored tests exercise real portable SQLite, authenticated storage, SyncManager, PluginRegistry, AgentManager and schedulers with an explicitly controlled local provider. A connector scenario uses the actual bridge engine/scheduler/credential store and durable SQLite cursor with a controlled allowlisted piece call; it proves owner reconstruction, not a packaged process or remote connector. Coverage includes ciphertext/marker reuse, independent read grants, inactive metadata, source/task scopes, cascade Stop/group guards, source mutation races, task lifecycle collisions, raw cancellation/drain, exact replacement binding, row-size preflight and redacted failure/no replay.

No worker validation has been executed. Root validation must record revision, command, fixture/schema, runtime/platform versions, artifact hashes and actual outcomes. Full #216 remains open for final production worker packaging/allowlist/pin/license evidence, call-scoped KV timeout/crash restart, final-identity warm/cold OAuth callbacks/refresh/revoke and representative retained connector behavior on packaged targets. Existing source bindings and controlled fixtures do not establish installed platform parity or authorize a release/data cutover.
