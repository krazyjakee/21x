# Production task source form controls

`TaskSourcePluginBackend` binds three retained form commands to the actual DatabaseManager, PluginRegistry, SyncManager, OAuthManager and registered authenticated-profile SecretStorage. The production owner supplies trusted desktop identity, current epoch and separate configuration, project, source, plugin, MCP, connector and credential-borrowing grants. These commands do not write tasks, source config or synchronization cursors. The existing `plugin:executeAction` stays with TaskLifecycleBackend and its actual task/source lifecycle owners.

| Command | Preserved result and authority |
| --- | --- |
| `plugin:list` | Genuine registered `{id,displayName,description,icon}` metadata, filtered by current plugin grants and configuration read access |
| `plugin:getDocumentation` | Genuine setup Markdown or `null`, with configuration read and exact plugin access |
| `plugin:resolveOptions` | Genuine bounded `{value,label}` options under the actual source-work owner, exact schema resolver and scoped credentials |

Schemas and actions remain in their existing renderer metadata path; the list API does not synthesize new schema/action fields. Input admits only the seven shipping plugin IDs and their declared resolver names. Resolver admission also checks the actual registered plugin schema. The retained Notion filter widget can request `data_source_properties`; its JSON property option values remain intact. Optional arguments retain the preload order `(pluginId, resolverKey, config, mcpServerId?, sourceId?)`, including an omitted fourth argument with a present fifth argument.

A saved-source resolver requires an explicit credential-borrow grant in addition to source/project read access. The source must exist, belong to the requested plugin and retain its authorized MCP/connector references. Saved secret markers resolve only to an existing nonempty string on that exact source. Unknown, missing, malformed or unsaved markers are refused before provider work. The borrowed config combines finite saved public fields, exact saved secrets and submitted form fields; it drops unknown internal fields and never sends the marker as a credential. Unsaved forms require a separate grant and accept only the existing finite task-source input config. They do not persist supplied credentials.

Source work uses SyncManager's actual FIFO admission and mutation fence. Accepted resolution stays owned until its raw provider/OAuth work settles, even after cancellation or a shutdown timeout. The boundary rechecks current grants, the actual plugin object, source project/plugin/MCP/enabled/config and relevant connector identity before execution and before exporting options. Normal synchronization timestamps may refresh without invalidating the form; changed source context suppresses the stale result. Requests are cloned before asynchronous authorization, so later caller mutation cannot change an accepted config. Shutdown fences new calls and drains retained work before SQLite/profile resources may be released. Cancellation never replays a provider call.

Stored source, connector and OAuth rows are bounded before their materializing getters. Individual rows and request/reply JSON frames cap at 512,000 bytes. Metadata caps at seven plugins; documentation at 128,000 UTF-8 bytes and UTF-16 code units; options at 512 records, with each value at 65,536 and label at 4,096 bytes/code units. NUL and extra output fields are rejected. Oversized results are refused rather than truncated. Known borrowed/submitted credentials and prior/refreshed OAuth tokens are redacted from reflected option labels, including common encoded representations. An option identifier containing a credential is refused, since replacing its value would invent an identifier. Unknown provider exceptions become fixed public failures without reflecting raw messages or config. Source credential storage formats and ciphertext remain unchanged by these reads.

Authored tests use actual portable SQLite, authenticated storage, registry, SyncManager and OAuth owners with an explicitly controlled provider fixture. Coverage includes metadata scope, exact marker loans/ciphertext preservation, schema admission, independent unsaved grants, MCP references, source mutation admission, raw cancellation/drain, changed context and revoked grants, request freezing, stored-size preflight, reflected credentials and actual OAuth refresh persistence. Codec tests cover all finite resolver pairs, optional argument holes, real Markdown/JSON option values, Unicode and exact bounds. No worker tests or checks were executed; the coordinator must record integrated validation results.

These three form controls do not establish full #216 acceptance. Packaged connector workers and retained remote behavior, final native OAuth/browser callback identity, call-scoped KV crash/restart evidence and installed-platform parity remain separate gates. No release or live-profile cutover is authorized by this implementation.
