Three negative regressions reproduced excess teardown on the previous Source implementation. An `agent:update`, `secrets:update` or subtree deletion could finish one held raw Stop, lose its caller grants, and still Stop the next owned session. The service now captures the original references and retains current authorization/cancellation through the manager's actual request scope. The manager rechecks immediately before storage and around awaited backend notification. Accepted storage is preserved if later refresh fails; the affected backend remains unavailable until an explicit successful authorized refresh. Accepted task scheduler follow-ups detach only after their database write, so expiry of the committing request cannot become the scheduler's future authority.

Two held model/provider reads also reproduced stale-result publication after an authorized default-endpoint change and withdrawal of the old endpoint grant. Reads now capture the exact backend/URL, pass that URL to the actual manager, reject a changed target before reply, and suppress old-target model-cache publication.

A two-backend configuration/credential change exposed another lifecycle gap: refusal by the first notification released the not-yet-refreshed destination/other backend. Two actual-root regressions reproduced new sessions starting on that stale cached backend. All accepted backends now remain failed until each own notification succeeds; an explicit authorized refresh clears only its acknowledged backend fence.

An actual missing-executable model query also exposed an unhandled Codex child-process `error`. The adapter now rejects pending RPCs on spawn failure/exit, uses fixed error wording, and joins the owned failed child. A retained service peer stays ready and answers subsequent reads. Controlled CLI discovery proves real process creation and teardown; it does not establish account authentication or paid inference.

The recurrence proof exposed a separate production event failure: a scheduler created a real task and published its raw private database row. Exact public event validation refused its private fields and stopped the service. The production event boundary now projects the task through the existing lifecycle projection before the existing exact `task:created` codec. Private MCP nonces remain private, and repeated recurrence reconciliation creates one instance without disconnecting the peer.

Credential proofs use synthetic values only. No values appear in recorded commands, events or evidence. The fixture provider can hold actual Chat, Commander and briefing streams while ignoring cancellation; a provider-key write fences new work, aborts all three, preserves the old key until all raw streams join, and only then commits encrypted storage. This demonstrates the registered production owner composition rather than a no-op mutation callback.

The learning proof starts a real controlled session, records the user's feedback/completion choice through `db:updateTask`, writes an actual workspace `SKILL.md`, and drives the real polling owner with controlled busy/idle status. Completion follows actual project-scoped skill synchronization and consumes the completion intent; it is not inferred from setting `agent_learning` alone. Source completion uses the actual SyncManager and never retries an uncertain accepted external action automatically.
