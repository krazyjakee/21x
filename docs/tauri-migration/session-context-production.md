# Production session context controls

`SessionContextBackend` binds `sessionContext:getSnapshot` and `sessionContext:setPolicy` to the production owner's actual SessionContextService and DatabaseManager. Both the service's database identity and the owner's borrowed-service lease are checked before work. Calls require host-established desktop identity and current engine epoch; a request body cannot grant its own task, project, agent, session or settings access.

The snapshot is the existing read projection over generations, model input occupancy, compaction/wakeup/turn counters, rollover settings and human summaries. It does not call a model, hydrate a transcript, start recovery, create a generation, deliver a wakeup or write lifecycle state. Reported and estimated usage remain distinct; unobserved occupancy stays `null` with source `unknown`. Commander occupancy uses the latest eligible model input in the current generation, rather than billing totals, summary requests or late calls in an older generation. Reading the controls adds no paid turn or automatic report reply.

Captain scope requires an actual `role = 'captain'` task, its project and its assigned agent, with separate read grants. Ordinary tasks and task groups cannot be presented as Captains. A project-scoped Captain read does not require a global configuration or Commander grant. Commander scope requires the global Commander read grant, the exact saved conversation grant and read access to every project referenced by its stored `commander_messages.project_id` values. Null project references preserve global conversation semantics. Both snapshots require read grants for `sessions.rollover` and `sessions.rollover_thresholds`.

Before the actual service deserializes saved data, SQL checks the lengths of scope references and the byte sizes of relevant task/agent rows, generation metadata, selected model fields, parsed lifecycle payloads, summaries, handoff summaries and policy rows. Commander project references cap at 256. Selected stored data caps at 512,000 aggregate bytes; the current generation caps at 100,000 lifecycle rows. Current-generation wake-disposition payloads are bounded before SQLite's JSON counter projection. Latest started/context usage and the ten selected summary/handoff/recovery records are checked before parsing. Foreign owner rows under the selected generation are refused. The read transaction keeps authorization, size checks and projection on the same database snapshot.

Unselected transcript/tool data, old billing calls and frozen handoff source histories are not materialized merely to display context. Oversized selected legacy records fail visibly without truncation or source mutation. Structured summary objects and arrays without human `text`, and malformed structured summary JSON, are refused rather than returning raw internal JSON through the service's legacy fallback; ordinary saved human prose remains readable. Normal structured summaries, continuation text and recovery recaps retain their original human content and provenance.

Results have exact nested fields, finite generation/handoff states and rollover reasons, nonnegative safe integer counters/timestamps, and explicit nullable usage/model/backend values. Summaries cap at ten records and 65,536 UTF-8 bytes/UTF-16 code units per content field; warnings cap at four records and 4,096 bytes/code units. Generation/model/reference strings cap at 4,096 bytes/code units. Replies cap at 512,000 UTF-8 JSON bytes. Extra raw payload/source/config fields, NUL, invalid numeric evidence and oversized results are refused.

Policy mutation requires global configuration write authority and explicit write grants for both settings. It invokes the actual SessionContextService transaction: either the mode and all thresholds persist together, or neither changes. The exact six fields are `mode`, `contextRatio`, `compactions`, `wakeups`, `turns` and `maxAgeDays`; modes are `off`, `observe`, `on`, context ratio is greater than zero through one, counts are integers from one through 1,000,000, and maximum age is greater than zero through 3,650 days. Defaults stay off, 70%, two compactions, 150 wakeups, 300 turns and seven days. Changing policy does not activate missing managed-runtime stages or immediately roll over a conversation.

Requests are cloned before asynchronous authorization. Cancellation before the effect prevents it; cancellation after an accepted transaction suppresses its reply without undoing or replaying the write. Accepted work remains retained through completion, and `close()` fences new calls and drains outstanding boundary work before the host releases the database. Errors use fixed public protocol messages.

Authored tests use actual portable SQLite/schema, CommanderStore, SessionLedger, TokenAccounting and SessionContextService. They cover genuine Captain/Commander projections, generation occupancy isolation, deduplicated counters, independent entity/settings grants, source preparse bounds, foreign generation evidence, human summary projection, real policy rollback, malformed input, cancellation after accepted persistence, exact owner identity and stale/foreign callers. Codec tests cover the exact preload shapes, nulls, finite states, numeric boundaries, Unicode/Markdown, aggregate limits and private-field refusal. No worker checks were run; the coordinator records integrated runtime/native/golden validation.

This slice does not close full #210 or #212. Remaining retained command/effect coverage, packaged Captain recovery/memory and background orchestration, interrupted startup/shutdown proofs, installed-platform parity and final evidence remain separate acceptance work. No release or live-profile cutover follows from these bindings.
