# Portable plugin manager ownership

`ClaudePluginManager` now requires an explicit absolute plugin directory. The application supplies its existing profile path. The portable manager contains no Electron import, lazy require or shared temporary-directory fallback.

Catalog fetching, discovery and installation retain their raw operations. Shutdown closes all read/write admission, clears the catalog cache, aborts source requests and joins accepted work before SQLite close. Ignored aborts and late body reads remain owned after a bounded close fails; retry joins the same work. Late catalogs cannot refill the cache, scans cannot advance to another marketplace, and completed downloads cannot publish plugins/resources after final shutdown.

The actual source downloader propagates cancellation through catalog fallback, GitHub recursion, raw-file fallback and URL downloads. Unused responses are cancelled. Late response bodies are checked before file writes, and shutdown errors do not trigger further fallback requests. Network failure logs omit reflected exception/URL contents. Acquisition now uses a private sibling staging directory and an exclusive per-name publication lock. Complete validated trees are renamed into the final directory. Failed or cancelled acquisition removes only staging and the lock created by that invocation; cleanup checks filesystem identity and refuses to delete replacement paths. Existing destinations, including partial installs, are preserved and require reconciliation before retry.

Installations that target the same directory name cannot run concurrently, including across marketplaces. A second installed plugin with that name is rejected to avoid overwriting the first plugin's directory/resources. Top-level plugin names must be single bounded identifier-like path components; invalid legacy names are refused before uninstall changes resources or removes files. Nested catalog paths, GitHub names/path fields, local source paths and manifest resource paths reject traversal, absolute paths, ambiguous Windows names and unsupported entry types. Tree inspection and bounded handle reads reject symlinks/junction aliases below the explicit source root, including manifest/resource reads. Resource materialization reads and validates the complete tree before database mutations, then derives names, directory structure and contents solely from that snapshot. Later directory/link swaps cannot introduce new resource reads. Snapshot reads also enforce the aggregate limit against actual bytes, including files that grow after metadata inspection. Historical cross-marketplace records sharing one name or overlapping resource prefixes are preserved: resource enumeration and destructive uninstall refuse the ambiguity with a manual-reconciliation error.

Limits are explicit: 1 MiB for catalog/manifest/URL JSON, 8 MiB per file, 32 MiB per tree, 2,000 entries, depth 16 and five HTTP redirects. HTTP response bodies are read with byte bounds; unused bodies and unfinished readers are cancelled and that cancellation remains part of the owned raw operation. GitHub fallback is limited to explicit API rate-limit responses; malformed entries and containment/size failures cannot trigger a fallback. URL archives and non-JSON downloads are explicitly unsupported. Local-copy traversal validates the whole source before copying and supports contained relative `pluginRoot` layouts.

Publication uses same-filesystem rename under a cooperative lock and refuses an observed destination. This is not a platform-native exclusive-rename primitive against hostile external filesystem mutations. Stale locks or historical partial/colliding installations are preserved for manual reconciliation; no automatic data deletion or migration is performed.

Thirty-three existing marketplace/install/resource controls now use the real portable SQLite manager. Eight new tests cover explicit paths, held catalog/download/body work, abort propagation, no late SQL/publication, queued discovery, concurrent/cross-marketplace collision rejection and unsafe top-level names. Tests use temporary directories, synthetic catalogs and controlled network responses; no marketplace or live profile is accessed. [Local evidence](evidence/plugin-owner-local.json) records exact results and source hashes.

New source/containment controls exercise staged publication, existing/during-download destination preservation, cancellation acknowledgement, redirect/body/tree limits, traversal, links, unsupported archives and resource preflight. A historical-collision manager control checks that both records, shared resources and files remain intact. Existing local resource fixtures now use separate source/install trees. Integrated local validation passed 5,488 application cases (20 optional skips) and 1,793 standalone/private-service cases (no skips), plus forced typecheck, source lint and builds. The prior evidence above predates these additions; [current batch evidence](evidence/issue-closing-20261013-local.json) retains commands, source/report hashes and exact scope.
