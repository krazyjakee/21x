# Actual agent desktop boundary

`src/service/agent-backend.ts` connects five retained desktop operations to the actual portable `AgentManager`, real SQLite and the deterministic adapter. It is restricted to synthetic mode, one explicitly approved fixture Agent and one actual task. Root bootstrap supplies the initialized database, held lifetime lock/liveness assertion, real manager/adapter, host-established caller identity, project access, validated event sink and fatal-event disconnect sink. The module does not create profile paths, choose adapters, enable SDKs/tools/credentials or grant native commands.

| Operation | Exact named wire payload | Actual effect/result |
| --- | --- | --- |
| `agent:getAll` | `{}` | Public projection of the approved fixture Agent only; no plaintext API keys/private columns |
| `agentSession:start` | `{agentId,taskId,skipInitialPrompt?}` | Authorized null assignment is written through actual `db.updateTask`, then `manager.requestSession`; preserve assignment if startup fails |
| `agentSession:resume` | `{agentId,taskId,sessionId}` | Actual manager reconnect or existing-owner return; verify exact persisted/live association and adapter identity |
| `agentSession:approve` | `{sessionId,approved,requestId,message?,responseType?}` | Actual manager permission response plus actual adapter decision confirmation |
| `agentSession:stop` | `{sessionId}` | Actual owner teardown with `requireAcknowledgement=true`, verified removal and adapter destruction |

Result codecs preserve declared started/queued, resumed/ended and success shapes inside `OptionalResult`. This fixture policy rejects `skipInitialPrompt:true`, question responses and workspace overrides. The `workspaceDir` positional slot accepts only its declared optional `undefined`, which is omitted; no renderer path is accepted or interpreted. Every approval requires the fifth positional API argument/nonblank named `requestId`, even though the shipping Electron API permits omission. Only declared optional message/responseType slots can contain `undefined`; no generic array conversion substitutes nulls or drops positional values.

Commands authorize the actual selected task/project and Agent. The task must be local, a normal top-level task, without source/scheduler/heartbeat effects; an existing foreign Agent assignment rejects. Session commands use the manager's exact session map key, never redirect aliases. They require matching persisted task session/Agent binding and the actual approved adapter instance. Resume additionally requires the requested persisted session ID and verifies the owner after returning. Existing live resume publishes an `agent:status` snapshot read from the actual owner, letting a reloaded renderer rediscover `waiting_approval` without running status-transition side effects. The snapshot omits activity metadata: it proves current owner state, not a fresh provider poll or periodic backend health.

Approval requires all three current facts: the exact live session is waiting, the real adapter's pending identity matches request/task/Agent, and the durable projection contains that request's running permission part. The actual adapter performs its final request identity gate. After `manager.respondToPermission`, the bridge verifies the newly recorded adapter decision matches request and Boolean choice. A stale, duplicate, foreign, missing or restored callback cannot return successful approval merely because the manager's legacy method resolved `void`. Restored provider callbacks are not reconstructed from historical cards. The Electron method/signature remains unchanged; this explicit confirmation applies only to the deterministic fixture.

The listener forwards seven exact event DTOs: public full `task:updated` re-read from SQLite, durable `transcript:changed`, `agent:status`, `agent:startQueueChanged`, project status/concurrency invalidations and recovery metadata. Status retains declared optional paired activity epoch/positive sequence and optional true heartbeat, separate from the service's global event sequence. The actual no-GUI fixture publishes transition metadata; Electron-only periodic GUI heartbeats do not establish portable freshness parity.

The actual start owner emits a durable `starting` queue claim before adapter creation and clears it after acknowledgement. Its queue event therefore admits zero or one exact public 17-field row, requiring selected task/project/Agent association, known state/reason, bounded counters/metadata, and fixed redacted errors. Private lease/workspace fields never enter the DTO. Raw partial task updates trigger a validated full public database re-read; private MCP nonces stay excluded. Transcript association/revisions are checked against persisted rows before delivery. Unknown or malformed critical events latch the backend unavailable and call the mandatory disconnect sink, because the actual manager catches listener exceptions. They are not quietly omitted. Shutdown stops/drains the real owner before disposing the listener exactly once.

Cancellation before effects rejects. Cancellation or delivery failure after an actual manager/adapter effect can leave an uncertain outcome; no automatic mutation replay or invented rollback is added. The root must preserve epoch/global sequence, reject stale replies and rehydrate task/transcript state after reconnect. Agent CRUD, sends, arbitrary sessions/paths, production profiles, live credentials, model SDK parity, browser features and real-provider approval parity remain unbound.

`scripts/agent-desktop-proof.mjs` stages the actual graph with the shared bounded lifecycle proof loader and explicit standalone Node-ABI SQLite. It uses a private synthetic profile and the real lifetime lock, requires no Electron shim/SDK factory, and reports fixed Boolean evidence/phase metadata without raw arguments or diagnostics. It checks scoped start, actual pending projection/event delivery, required/stale/duplicate approvals, pending live-resume status snapshot, acknowledged stop, owner/profile recreation, restored stale callback rejection, actual rejected permission, durable snapshot/delta, critical-event failure and single listener removal. Additional turns come only from the internal proof's actual manager send method; no desktop send command is granted. The narrow staged proof passed 85 modules/30 validated events, including pending live-resume status, with zero warnings/errors; full integration checks and installed UI evidence remain the batch owner's responsibility.
