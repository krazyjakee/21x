# Task lifecycle service boundary

`TaskLifecycleBackend` ports ten retained task commands through the actual database, AgentManager, source sync, recurrence, heartbeat and automation owners. Its full task codecs replace the synthetic `DatabaseBackend` task CRUD only when a production owner is attached. The finite operation manifest and codecs alone grant no effects.

| Command | Authority and actual effect |
| --- | --- |
| `db:getTasks`, `db:getTask`, `db:getSubtasks` | Trusted caller/epoch, task and project read access; declared public task fields; hidden execution rows excluded from discovery |
| `db:createTask` | Destination project and parent/template/reference authority; database create, real recurrence initialization and automation trigger; execution requests enter actual admission |
| `db:updateTask` | Existing and destination project/task/reference access; actual lifecycle lease, user feedback validation, recurrence/heartbeat/automation and parent review effects; execution enters actual admission after the lease releases |
| `db:deleteTask` | Every affected descendant, parent and sibling scope checked before Stop; actual live/pending/queued teardown and heartbeat cleanup; deepest descendants receive attachment/transcript cleanup before cascade deletion |
| `db:reorderSubtasks` | Exact complete set of current authorized children; actual ordering write and correlated update events |
| `project:moveTask` | Source/destination projects and every descendant/reference checked; acknowledged owned teardown before the database's atomic subtree/recurrence move |
| `tasks:getCoordinatorTaskId` | Project read access; returns the production-seeded Captain identity without turning a read into a hidden-row mutation |
| `plugin:executeAction` | Exact current task/source association, task/project/source write authority and actual registry's declared source actions (plus the legacy Complete alias); real `SyncManager.executeAction`, source acceptance and local projection; accepted work is not replayed after cancellation |

The backend requires actual registered recurrence, heartbeat and automation identities. `assertTaskLifecycleOwners` refuses missing or substituted hooks; it does not supply successful no-op callbacks. `runTaskLifecycleMutation` fences session dispatch and joins raw lifecycle work with the actual manager's shutdown. Assignment and reparenting acknowledge the current owner's Stop before writing. Working status cannot be manufactured by plain database CRUD. An unassigned execution request follows the existing triage path; admission may leave work queued rather than immediately running.

Public CreateTaskDTO/UpdateTaskDTO fields are exact and bounded, including output values, attachments, feedback, snooze, recurrence, heartbeat and successor links. Client-provided role, group, source-link, native-session and project-update fields are rejected. Captain/group execution rows cannot become ordinary tasks or be deleted here. Group member lifecycle and source actions remain with group controls. New repositories must belong to the selected project; existing authorized task repositories remain valid in place. Cross-project reparenting of a task with descendants is rejected because the legacy database operation moves only its direct row. Use the atomic top-level project move instead. Invalid recurrence, cycles, non-sibling successors and unfinished-child completion are rejected before lifecycle effects.

Direct source completion with `db:updateTask` cannot bypass source confirmation. The user may explicitly complete locally with `complete_at_source:false`; otherwise the source action owns confirmation. Feedback records the selected rating and completion choice through `updateTaskFromUser`; the learning prompt and eventual skill synchronization remain with the existing session lifecycle. This boundary does not claim that a stored learning status alone ran a model or completed its source.

Requests/replies/events cap at 900,000 UTF-8 JSON bytes; task lists and affected sets cap at 128 records. Oversized records/results fail visibly and are preserved in storage. They are not silently truncated. Only declared public task fields are projected; private MCP nonces, legacy storage columns and source credentials are excluded. Missing task reads/updates preserve undefined and missing deletion preserves false when host authority permits the requested identity. Event codecs retain exact task association and accept declared partial lifecycle updates.

Cancellation before a database/source effect prevents it. Cancellation after accepted work suppresses the reply while preserving reconciliation and invalidation. Raw Stop/source flights remain owned until they settle; `close()` closes admission and joins them. A timeout requires the host to retain SQLite, the profile lock and lifecycle/source owners. Fatal event delivery is latched after an accepted effect rather than retrying that effect. Native ingress must supply caller/epoch/scope; payloads cannot mint identity.

The new tests use actual portable SQLite, DatabaseManager, AgentManager and schedulers with an explicitly controlled adapter/source plugin. They cover DTO/UTF-8 bounds, authority before Stop, real admission/teardown, subtree cleanup, exact child ordering, feedback choices, recurrence/heartbeat/project events, source rejection/acceptance, cancellation/drain and accepted notification failure. These fixtures do not establish real provider/connector or installed-platform parity. Integrated checks and revision/runtime/schema/hash/expected-result evidence belong to the coordinator.

Full #210/#202 remain open. Checkpoints use the separately owned production `agentSession:approve` live-request boundary; no duplicate or synthetic approval handler is added here. Separate durable checkpoint semantics, the complete learning send/skill-sync workflow, overdue/limit settings, remaining heartbeat commands, encrypted credential formats, all retained command/event reconciliation and installed native parity require their own owner integration/evidence. No release, live-profile conversion or data cutover is established by this task-domain slice.
