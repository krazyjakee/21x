# Configuration codecs and forwarding ownership

This G1 batch reviews eleven generic event forwarding sites after the actual AgentManager extraction, supplies codecs for 22 retained configuration operations, and provides real database bindings for the 18 skill/project/repo/resource operations. The content bindings are now composed into the disposable synthetic service, exact native policy and isolated renderer client. Production configuration UI and owner integration remain open. Existing Electron handlers remain unchanged.

## Ten forwarding sites

The authoritative finite map is `event-forwarding-review.json`; `scripts/tauri-contracts.mjs` copies it into the operation manifest and generates `src/shared/desktop-event-forwarding.ts`. The source base and exact file/line/column/callee expressions are recorded. Generation fails if a dynamic site is unreviewed, duplicated, or its review location becomes stale. Channel ownership must agree with the retained operation manifest; namespace wildcards and removed operations cannot satisfy the review.

`transcript:changed` uses the durable projection sender directly, outside Agent Manager `broadcast`. The review distinguishes accepted producer inputs, persistence-only branches, and actual outgoing names. Tests preserve this distinction and the speech/audio destination boundary.

The AST evidence remains `channel: null` with its original unresolved expression: the parser has not inferred runtime values. The manifest separately records eleven reviewed references and zero unreviewed references. Core host calls carry the channel in argument one; the scanner explicitly records that position and the new dynamic dispatch rather than hiding it after extraction. These are manual source ownership maps, not installed validators, permissions, or closed-world guarantees about future code. Every portable event still needs its concrete payload schema, producer authority, targeted destination, epoch, sequence, and overflow/recovery policy.

## Twenty-two configuration codecs

`src/shared/configuration-desktop-codecs.ts` exports `CONFIGURATION_COMMAND_CODECS` with the same structural methods as the existing database/renderer client codecs. Named payloads use `{ data }`, `{ id, data }`, `{ projectId, data }`, `{ id }`, `{ projectId }`, or `{ projectId, orderedIds }` according to the actual method signature. Archive's optional Boolean stays omitted when absent and preserves explicit false. Skill scope uses an explicit null for global scope. All results retain `OptionalResult<JsonValue>` and actual undefined/Boolean/record distinctions.

| Operations | Codec scope | Registration prerequisite |
| --- | --- | --- |
| Agent get/create/update/delete | Declared metadata/configuration fields, referenced IDs, HTTP(S) server URLs, model/backend/auth/sandbox enums and positive concurrency values | Trusted profile editor; referenced Agent/MCP/skill/secret IDs authorized; live update requires the actual `drainStartQueue` callback, live deletion requires reference/session reconciliation |
| Skill get/create/update/delete/setProject | Declared content/version/model/scope fields, confidence, usage, tags, nullable model/project | Project/global scope authority; destination project exists; optimistic version conflict rejects without overwrite and gets a stable error mapping |
| Project update/archive/reorder | Content/git fields, archive Boolean and exact ordered IDs | Database default-project rules, authorized project scope; settings/default-agent/Captain fields remain rejected until real queue/Captain effects are connected |
| Project repo list/add/update/remove/reorder | Declared repo/provider/org/branch metadata | Every referenced child belongs to the authorized project; metadata does not authorize git/network/filesystem work |
| Project resource list/add/update/remove/reorder | Declared label/URL/notes metadata | Every referenced child belongs to the authorized project; URL text does not authorize opening an external URL or reading a file |

Arrays are capped at 128 and records/strings have explicit bounds; transport frame limits still apply. Large lists/content require pagination/chunking before full parity can be claimed. Unknown fields, undeclared binary values, malformed references, and invalid missing/null shapes fail with redacted protocol errors. Optional undefined fields are omitted only where their declared schema permits it; there is no generic recursive conversion.

Public Agent projection selects the declared metadata/configuration keys, omits plaintext `api_keys` and private database columns, and retains secret IDs as trusted desktop assignment metadata. The shipping desktop IPC currently returns the complete Agent config; mobile already strips sensitive fields. This portable boundary deliberately blocks plaintext key reads/writes and awaits credential-owner integration. A future config replacement must preserve the existing hidden credential bucket or use an explicit credential transaction; omission from a DTO must never silently delete stored credentials. No database behavior or stored rows are changed by these codecs. Skill projection omits the internal deletion marker, preserving BOM/Unicode content and version cursors. Project configuration replies reject credential/private fields in generic settings rather than expose them or rewrite persisted data.

`src/service/configuration-backend.ts` binds the 18 non-Agent operations to an injected, initialized real `DatabaseManager`. It owns a separate exact registry and operation schema map for the bootstrap to compose. It does not open a database, choose paths, install credential providers, acquire/release the profile lock or register native commands. The owner must inject its actual lock/database liveness assertion and trusted host caller check. Project access explicitly distinguishes reads and writes. Global skill reads, global skill writes, scope changes and profile-wide project reorder each require explicit grants; request payloads cannot select the caller or grant themselves scope.

Skill reads filter unauthorized projects. Every update/delete authorizes the existing row; a scope move additionally authorizes its destination and requires the explicit scope grant, including promotion to global. Project targets must exist. Moves into one project reject foreign task references and Agent-level defaults, preserving usable scope instead of silently stranding assignments; this matches the Commander's conservative move behavior and is stricter than the current desktop IPC setter. Duplicate active skill names reject without revealing the colliding row. `expected_version` remains optional to preserve the API; when supplied, actual database optimistic conflicts map to `SKILL_VERSION_CONFLICT` with the fixed message “The skill changed. Reload it before writing.” No IDs, expected/current versions or input text enter that error. The protocol/native error tables must share that code before integration.

Repository/resource updates and removals authorize their existing parent project. Reorders require an exact complete set of that project's children, not just a set of individually well-formed IDs. Profile-wide project reorder requires every stored project, including archived ones, an explicit reorder grant, and write access to all of them. The Default project cannot be archived. Metadata changes reject settings/default-Agent/Captain fields; resource URL text remains context metadata, with no file or navigation effect.

Each operation repeats authorization in the actual SQLite transaction after the registry's asynchronous authorization boundary. Public result projection and event metadata validation run before commit, so malformed results roll back effects. Only committed changes emit `skills:changed` or `project:changed` invalidations. The sink must preserve the service's global epoch/sequence and disconnect/rehydrate on event delivery failure. An event sink failing after commit makes mutation outcome uncertain; callers must not replay it automatically. Missing skill/child updates preserve `undefined` and missing deletes preserve `false`; foreign existing rows reject. Existing project settings containing private credential/nonce fields reject before content writes, without reading them into the reply or rewriting them.

`scripts/configuration-proof.mjs` reuses the small portable transpile graph with explicitly selected standalone Node SQLite. `TAURI_SQLITE_MODULE` must be an absolute staged Node-ABI `better-sqlite3` package path, and `TAURI_NODE_RUNTIME` selects Node for the opt-in test. It never uses Verify's Electron-rebuilt native addon as a fallback. The proof creates a private temporary profile, holds the actual profile lock, and checks scoped CRUD, source/destination authority, conflict preservation, complete reorders including archived projects, revoked permission across the await boundary, cancellation, an actual INSERT rolled back after malformed result injection, durable reopen and Agent CRUD remaining unbound. Its report contains fixed proof names; dependency diagnostics are redacted. Tests and builds remain deferred to the integration batch.

The four Agent CRUD operations remain codec-only and unbound pending their actual lifecycle owner. `CONFIGURATION_OWNER_REQUIREMENTS` records effects that cannot be replaced with a no-op callback. No lifecycle, start/resume/stop, permission approval, or synthetic approval handler is added. G1 still needs the remaining retained command/event schemas, native callback codecs, caller/domain permissions, byte/undefined rules, large-payload recovery and installed host evidence.
