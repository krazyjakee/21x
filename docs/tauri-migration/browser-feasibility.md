# Browser feasibility foundation (T02 / #198)

This preparation step inventories the actual browser behavior and implements an internal policy/session contract. It does not create native browser panels or satisfy T02. [Issue #198](https://github.com/krazyjakee/21x/issues/198) covers this foundation; [#193](https://github.com/krazyjakee/21x/issues/193) retains the full browser feasibility gate. No platform has demonstrated browser parity in this batch, and D5 remains open.

## Existing behavior to preserve

The baseline is [BrowserPanelContent.tsx](../../src/renderer/src/components/canvas/BrowserPanelContent.tsx), [panel-browser-broker.ts](../../src/main/panel-browser-broker.ts), [browser routes](../../src/main/task-api/browser-routes.ts), [recording scripts](../../src/main/browser-recording-scripts.ts), [durable recording storage](../../src/main/browser-recording.ts), and browser setup in [main/index.ts](../../src/main/index.ts). This is an Electron WebContents broker, not a general CDP browser.

The renderer registers stable canvas panel IDs and linked tasks. Broker tools address only registered, task-linked WebContents; an omitted panel ID is accepted only when exactly one panel is linked. The panel is a real `<webview>` within the canvas, with URL/title persistence, history, refresh, cache-bypassing refresh, loading status, authentication recovery, recording controls and lifecycle cleanup. It has no explicit partition attribute, so current panels use the default session rather than independent cookie stores.

Snapshot/action scripts label at most 120 interactive elements with agent references, redact sensitive input values, and perform clicks, typing, keys, scrolling, text reads and waits. Scripts have finite outer deadlines. Console capture keeps 200 entries per panel. Network tooling reads bounded page performance entries; it does not expose request/response headers or bodies. Screenshots are real PNG files from `capturePage`.

Recordings capture human and agent actions, before/after DOM snapshots, navigation and explicit gaps. They run in Electron isolated world 998, with per-recording nonces, console-message delivery, ordered writes, field/URL redaction, stop/flush behavior and interrupted manifests. Saved recordings remain task-scoped after the native panel closes. A plain initialization script in the page world does not establish this isolation.

The current host removes guest preload/Node privileges, denies guest media permissions, denies popups while opening accepted URLs externally, modifies embedding/security headers and client hints, injects compatibility patches, and supports an external Chrome authentication/cookie-import path. Non-media permissions are currently granted by the default-session handler. Changes to that behavior need an explicit product decision, rather than an assumption that default denial is feature parity.

Exact pinned-source compatibility and compilation remain unverified here. “Candidate” below means an API path to prototype; every row still needs packaged evidence on Windows WebView2, macOS WKWebView and Linux WebKitGTK.

The native adapter is a candidate requiring platform-specific work. An iframe or external browser link cannot demonstrate this matrix. If a required row has no viable implementation, record its failed proof and propose a concrete browser-helper or scope decision before a parity release.

The builder documentation also warns of Windows deadlocks when creating views from synchronous commands/event handlers; native creation must use the documented asynchronous/threaded path. [Creation constraints](https://docs.rs/tauri/2.11.4/tauri/webview/struct.WebviewBuilder.html#method.new)

## Delivered policy/session contract

[browser-policy.ts](../../src/shared/browser-policy.ts) normalizes explicit HTTP(S) URLs and rejects application schemes, userinfo, malformed/control-character input and native transport hosts. It accepts public sites, representative intranet hosts, loopback development apps, IPv6 and Unicode hostnames. Configured application/API origins are excluded; owners must supply the actual development server and per-launch API origins, including applicable aliases. This is a navigation boundary, not an SSRF claim or DNS/IP network sandbox. It preserves query strings and fragments for actual navigation; logging and recording owners still must redact them.

[browser-authority.ts](../../src/shared/browser-authority.ts) is an internal service-owned registry. It performs no navigation, evaluation, capture or native permission calls. The authenticated session owner creates opaque session objects with explicit operation grants and `ask`/`allow` policy. Caller-created copies cannot acquire authority. Registered panels have exact native IDs and task links; protected IDs, duplicate labels and implicit selection of multiple panels fail closed. Main/trusted native views must be passed in `protectedViewIds`.

Every operation needs an adapter-supplied request validator. There is no generic eval operation. Navigate additionally validates `{ url }` through the URL policy. Tickets bind the exact panel generation, session, operation and cloned/frozen arguments before approval. Tickets are process-local and must never be serialized into a remote page. The service correlates HITL responses, starts each ticket once immediately before native dispatch, and completes it on every success/failure. A false completion result discards a late callback after revocation, task-edge changes, panel disposal or authority disposal. Running tickets retain capacity until native work settles, even when aborted. Abort is advisory and cannot reverse a committed action.

The registry caps panels, sessions and total outstanding tickets at 128, tasks per panel at 128, request JSON at 64 KiB and navigation input at 8192 characters. An owner must additionally impose finite approval/native deadlines and call `cancelOperation`/`finishOperation`; this class supplies no timers or native cancellation mechanism. Reconfiguration invalidates existing panel tickets, including for retained task links, so adapters must surface interruption and issue fresh work explicitly.

The isolated spike's remote permission decision is always `deny`. Native adapters must enforce it on every permission callback; this policy has not been connected to a WebView. It does not control microphone permission for the trusted desktop voice flow, and must not silently replace the production Electron non-media behavior.

Remote WebViews get no remote capability entries, wildcard trusted-view grants, task APIs, event subscriptions or privileged preload. Register custom commands in the native app manifest and enforce actual caller WebView identity/origin in handlers. Tauri documents that app commands are otherwise broadly available, and overlapping capabilities combine their grants. [Tauri capability model](https://v2.tauri.app/security/capabilities/)

## Next bounded native spike and gate evidence

1. Add two real HTTP(S) child WebViews to the isolated runtime, with exact labels and no application bridge grants. Feature-enable/pin the required child-view API through the runtime owner. Use a small local test site and a representative public/intranet site; retain their actual URLs and origins.
2. Prove geometry, focus, redirects, history and lifecycle first. Register the native labels from the trusted host; map task/session identity in the service through the policy. Probe every privileged command family from each remote page, iframe and popup, and verify denial despite page-created invoke-shaped objects.
3. Implement a real evaluation result path, finite deadlines and two-page navigation races. Capture one real screenshot through each platform SDK. A missing API returns an explicit unsupported failure; do not produce synthetic screenshots or successful empty snapshots.
4. Demonstrate browser/app storage separation and login persistence on every supported macOS/Windows/Linux minimum. Decide shared remote cookie groups and non-media permission policy from the baseline/product requirements.
5. Demonstrate isolated-world recording plus console/network capture under page spoofing, rapid navigation, hidden panels, overflow, stop/flush and disposal. Reuse durable recording semantics and saved task authorization; native events alone do not establish persistence.

[browser-authority.test.ts](../../src/shared/browser-authority.test.ts) supplies in-memory, host-neutral regression cases for URL boundaries, intranet access, exact task/panel selection, protected labels, forged capabilities, approval argument binding, adapter/argument denial, task-link races, disposal/reused IDs, revocation, capacity, permission denial and late result suppression. No tests, native compilation or installations ran while writing this batch; the coordinator runs focused validation at batch end. These tests are authority evidence only, never proof of WebView isolation or browser parity.
