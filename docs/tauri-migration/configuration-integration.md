# Synthetic content configuration integration

This page records the earlier diagnostic slice. Current production project editor
fields, actual Captain/queue effects and scoped invalidation are described in
[production project configuration](production-project-configuration.md). Its
production override leaves the content-only diagnostic restrictions below intact.

Scoped continuation for [#210](https://github.com/krazyjakee/21x/issues/210) and [#202](https://github.com/krazyjakee/21x/issues/202). The existing 18 content-only bindings now share the actual packaged synthetic service's database, writer lock, caller identity, epoch and event sequence. This advances the debug slice from 20 to **38 commands** (15 database, 18 content configuration, 5 fixture-agent). All 38 remain scoped synthetic declarations; production readiness and Electron retirement remain false.

`ConfigurationBackend` is instantiated only after the same owned initialization as `DatabaseBackend`. It never chooses another profile, opens another state writer or supplies a substitute lifecycle owner. Its availability assertion rejects closing service, missing lock or closed database and checks the actual lifetime lock. The marked temporary profile grants content editing to the private host pipe; native trusted-window authorization still precedes forwarding. Live profiles and production scope grants remain unimplemented.

The Rust engine uses an explicit `configuration_desktop` policy for all 18 operations. Native and TypeScript checks preserve named payloads, exact fields, UTF-16 string limits, nullable scope, archive false/default semantics, complete unique ID lists, public result shapes and undefined/void results. The engine forwards `skills:changed` metadata alongside the existing `project:changed` event. The isolated renderer declares these event codecs so legitimate configuration invalidations cannot disconnect it as an unknown event. The full production configuration renderer is still outside this build.

Agent create/update/delete remain unbound. Project settings/default-agent/Captain edits, plaintext credentials, arbitrary file/path access and git/network work remain outside these content operations. Repository/resource metadata does not grant external effects. Existing transactional authorization, result-before-commit projection, version conflict mapping, complete reorder validation and scope-change reference checks remain owned by `ConfigurationBackend` and the actual database.

The new [private-pipe proof](../../scripts/configuration-service-proof.mjs) exercises every content command against the staged Node 22.23.2 / SQLite 13.0.3 service. It checks effects, archive/default-project protection, full project/child reorders, foreign child rejection, optimistic conflicts without writes/events, cancellation before effects, missing-result semantics, scope moves, fixed invalidations, rejected lifecycle edits, denied Agent CRUD and persistence across service shutdown/reopen with a fresh epoch. Both services acknowledge normal exit before the temporary profile is removed.

An opt-in native engine test exercises all 18 operations through actual `desktop_request` request/result validation and real service events, including version conflicts, foreign reorders, stale epochs and owner-bypass rejection. Both packaged platform workflows execute the service proof and native roundtrip with the same staged resources before packaging. Verify now runs synthetic native policy unit tests and builds the isolated frontend. Prepared jobs do not count as hosted or installed evidence for this source revision.

The separate scoped authorization/rollback proof is retained because the broadly granted disposable profile cannot demonstrate denied production scopes. Full task lifecycle, settings/credential semantics, Agent CRUD/queue effects, production profile authority, complete large-list behavior and configuration UI remain #210 work. No migration acceptance gate is closed by this integration.

Latest [local evidence](evidence/issue-continuation-local.json) records all real service proofs, 20 native unit + 6 staged cases, successful native host compilation, and a full enabled regression run with 5,148 passed / 4 skipped in 363 files. It also identifies the exact working-tree source and staged-resource hashes. Typecheck, changed-source/full lint, builds, workflow syntax and inventory/contract freshness passed. Full lint retains 165 existing warnings. Historical installed evidence remains tied to its earlier source.
