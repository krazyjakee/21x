# Git provider contracts in the production native host

The production service has fifteen explicit Git provider operations. The native desktop facade preserves the existing `github`, `gitlab`, `forgejo`, and `git.recordRepoProviders` APIs. The Rust production policy admits only those finite operation names and their exact payload keys; Node applies the actual shared Git provider codecs and owner authorization again before accessing a provider.

CLI status, organization and repository queries, and pull request details can run during durable recovery. `forgejo:setLogin` and `git:recordRepoProviders` wait for facade hydration. Each request belongs to the current engine epoch. Reconnect recovers durable state without repeating an accepted login or repository-map mutation. A missing provider backend returns an explicit unavailable capability; an installed/authenticated status remains the actual provider result.

The codecs bound repository and organization counts, UTF-8 text, pull request bodies and checks, and complete wire results. GitLab organization inputs allow nested namespaces. GitHub and Forgejo organization inputs accept a single segment. Pull request references accept reviewed GitHub `/owner/repo/pull/N` or Forgejo `/owner/repo/pulls/N` HTTP(S) forms. URL DTOs contain no credential userinfo, signed query, or fragment. Tea errors use fixed public messages; native validation refuses raw errors, extra private DTO fields, unknown providers, marker/token names, and arbitrary process or path fields. Recording repository providers returns JavaScript `undefined`, represented solely by `{defined:false}` on the wire.

This integration adds no native OS routes or events. The finite production service registry has 176 commands; the facade additionally has two separate native services, for 178 bindings. Existing 23 service event contracts remain unchanged. Native and facade regressions cover every Git operation, malformed authority fields, public projections, bounds, hydration, unavailable capabilities, and accepted mutations interrupted by reconnect. Live CLI credentials, actual provider network behavior, and installed cross-platform acceptance remain separate verification work.
